# OSM Iso Buildings

Изометрическая 3D-визуализация зданий OpenStreetMap для видимой области карты.
Высота зданий подтягивается из тегов OSM (`height`, `building:levels`), для
зданий без этих данных используется оценка по типу застройки.

## Как это работает

1. Пользователь двигает 2D-карту (MapLibre GL, тайлы OSM) и находит нужный участок.
2. По нажатию «Построить 3D» текущие границы viewport (bbox) уходят в
   [Overpass API](https://overpass-api.de/) — запрашиваются все `way`/`relation`
   с тегом `building` в этой области.
3. Контуры зданий проецируются из lat/lon в локальные метры (equirectangular
   проекция относительно центра области).
4. Каждое здание экструдируется в 3D (Three.js, `ExtrudeGeometry`) на высоту:
   - **height** из OSM — если тег указан явно (точный источник);
   - **этажи × 3 м** — если указан `building:levels`;
   - **оценка по типу** (`building=house/apartments/...`) — если данных нет вовсе.
5. Сцена рендерится в изометрической проекции (ортографическая камера,
   классический угол ~35.264°), сцену можно вращать перетаскиванием мыши,
   масштабировать колесом мыши / pinch-жестом на тачскрине.

В 3D-виде дополнительно отображаются:
- **номера домов** — подписи над крышами зданий с тегом `addr:housenumber`;
- **компас** — стрелка "N" в левом верхнем углу, показывает направление на
  север при любом повороте сцены;
- **трассировка риска** — лучи в направлении границы/угрозы и маркеры
  ближайших опасных объектов с подписями, если они попадают в текущий
  масштаб вида (подробнее — ниже).

Источник высоты каждого здания подсвечен цветом — легенда внизу слева.

## Оценка риска — мультилучевая схема

При клике по зданию риск считается не с одной ближайшей точки границы, а
сразу по **18 направлениям**, равномерно распределённым по всей линии
границы РФ/Украины (`src/border.ts`). Для каждого направления отдельно
пересчитываются:

- расстояние и азимут от дома до этой точки границы;
- маскирование рельефом (профиль высот от Open-Meteo — все 18×13 точек
  запрашиваются одним пакетным HTTP-запросом, чтобы не упираться в
  рейт-лимиты);
- экранирование соседними зданиями **именно с этого азимута** (здание может
  закрывать один угол подлёта и быть бесполезным для другого);
- ориентация окон относительно конкретного направления.

Итоговый балл берётся по **худшему из 18 направлений** (наихудший вероятный
сценарий, а не усреднение), но в 3D-сцене визуализируются сразу несколько
лучей (топ-5 по риску) — основной ярко, остальные тоньше и прозрачнее, чтобы
было видно веер возможных углов подлёта, а не один "правильный" вектор.

Объекты повышенного риска (военные/промышленные/энергетические) ищутся один
раз в радиусе 5 км вокруг дома и не зависят от направления — считается, что
их наличие рядом повышает риск независимо от конкретного азимута подлёта.

### Ручной акцент (опционально)

Под компасом в 3D-виде есть переключатель «ручной акцент» — пользователь
может перетащить две ручки на дуге компаса, чтобы задать сектор азимутов, и
слайдером — насколько его усилить (+0…+50%). Направления границы, попавшие в
этот сектор, получают множитель к своему расчётному баллу ДО выбора худшего
сценария — то есть акцент может по-настоящему повлиять на итоговую оценку,
а не только перекрасить картинку.

Это **явно помечено как предположение пользователя**, а не выведенный из
данных факт — отдельной строкой в результатах и отдельным цветом лучей в
3D-сцене (фиолетовый — акцентированные направления, янтарный — прочие
проверенные, основной цвет уровня риска — худшее направление). Сектор задан
в абсолютных азимутах и не зависит от текущего поворота 3D-сцены.

## Ограничения

- Overpass API — публичный сервис с рейт-лимитами. Для собственного продакшена
  с высокой нагрузкой стоит поднять свой инстанс Overpass или кэширующий прокси.
- Приложение сознательно ограничивает область запроса (см. `MAX_AREA_KM2` и
  `MIN_ZOOM_FOR_3D` в `src/main.ts`), чтобы не отправлять в Overpass слишком
  тяжёлые запросы и не вешать рендер на тысячах зданий разом.
- Обработка `relation` (multipolygon) упрощена: берутся только внешние (`outer`)
  кольца, `holes` (внутренние дворы/вырезы) не учитываются. Для подавляющего
  большинства зданий это не критично.
- Высота без тегов в OSM — это **оценка**, не факт. Здания без точных данных
  явно помечены на карте (серый цвет + легенда).

## Разработка

```bash
npm install
npm run dev       # локальный сервер разработки
npm run build     # прод-сборка в dist/
npm run preview   # локальный просмотр прод-сборки
```

## Деплой на GitHub Pages

Проект уже настроен под автодеплой через GitHub Actions
(`.github/workflows/deploy.yml`).

1. Создайте новый репозиторий на GitHub и запушьте туда этот код:

   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<ваш-юзернейм>/<репозиторий>.git
   git push -u origin main
   ```

2. В настройках репозитория: **Settings → Pages → Source** выберите
   **GitHub Actions** (не "Deploy from a branch").

3. После пуша в `main` workflow соберёт проект и задеплоит `dist/` —
   сайт появится на `https://<ваш-юзернейм>.github.io/<репозиторий>/`.

Файл `vite.config.ts` уже использует относительный `base: './'`, поэтому
дополнительно указывать имя репозитория в конфиге не нужно — работает на
любом подпути.

## Стек

- [Vite](https://vitejs.dev/) + TypeScript

- [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API) — данные OSM
